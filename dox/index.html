September 2026 · Agent Harness Hackathon · project lead, team of three

An on-call agent for a checkout service. When errors spike, an incident monitor opens a session on its own. Two read-only subagents check the logs and the recent commits in parallel. The agent then proves the cause with a test that fails at the bad commit and passes at its parent in a Daytona sandbox, opens a revert pull request, and waits for a human to approve the merge. Once the fix is deployed, it checks that recovery is real and files the postmortem.

The hard part

Trust. Logs are treated as data, so a planted line telling the agent to delete main gets flagged and ignored. Recovery only counts once 30 or more requests over 30 seconds come back under 1% errors, so an empty traffic window cannot pass for a fix.

My part

I owned the harness setup, the agent's instructions and runbook, the approval gates and the parallel subagents. Robert Lagidze and Aldi built the demo service, the monitoring and the sandbox flow with me.

Built with

Python, TrueForge, MCP, Daytona, FastAPI, SQLite.
